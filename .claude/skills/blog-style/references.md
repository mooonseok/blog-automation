# blog-style 규칙의 출처

2026-10-28 조사. 규칙은 모두 내 말로 바꿔 썼다. 원문을 그대로 옮기지 않는다.

| 출처 | 라이선스 | 가져온 것 |
|---|---|---|
| [토스 「개발자를 위한 글쓰기 기본기」](https://technical-writing.dev) | CC BY-NC-SA 4.0 | 가치 먼저, 개요(요약) 두기, 결론형 소제목·어미 통일·30자, 예측 가능한 구조, 메타 담화 제거, 구체적으로 쓰기, 진행/수행 제거 |
| [NN/g Inverted Pyramid](https://www.nngroup.com/articles/inverted-pyramid/) | 저작권 있음 (요약만) | 핵심 한 문장 먼저 정하기, 모든 단위에서 앞쪽에 핵심 |
| [NN/g F-shaped Pattern](https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/) | 저작권 있음 | 첫 두 문단에 핵심, 소제목은 정보 단어로 시작, 핵심어 굵게 |
| [NN/g Formatting Long-Form Content](https://www.nngroup.com/articles/formatting-long-form-content/) | 저작권 있음 | 라벨 붙은 요약 상자, 굵은 글씨 절제, 콜아웃 블록 |
| [NN/g Writing Hyperlinks](https://www.nngroup.com/articles/writing-links/) | 저작권 있음 | 도착지를 말하는 짧은 링크 텍스트, "여기" 금지 |
| [Google Technical Writing: Paragraphs, Lists and Tables](https://developers.google.com/tech-writing/one/lists-and-tables) | CC BY 4.0 | 문단 첫 문장에 요점, 한 문장 문단 금지, 표·목록 앞 도입 문장, 표 셀 짧게 |
| [obra/the-elements-of-style](https://github.com/obra/the-elements-of-style) | 원전 퍼블릭 도메인 | 한 문단 한 주제, 주제문, 불필요한 단어 빼기, 병렬 구조 |
| [blader/humanizer](https://github.com/blader/humanizer) | MIT | 장식용 굵은 글씨·라벨 나열 제거, 예고성 서두·판에 박힌 마무리 제거, 구분선 제거, em dash 제거 |
| [DaleSeo/korean-skills humanizer](https://github.com/DaleSeo/korean-skills) | MIT | 한국어 AI 문체 패턴과 S1~S3 우선순위 |
| [anthropics/skills doc-coauthoring](https://github.com/anthropics/skills/tree/main/skills/doc-coauthoring) | 저장소 표기 확인 필요 | 다 쓴 뒤 독자 테스트 |
